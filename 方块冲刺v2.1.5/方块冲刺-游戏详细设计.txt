## 〇、先看这一章：改了什么，为什么改

### 0.1 硬约束

| 约束         | 后果                                     |
| ---------- | -------------------------------------- |
| 朋友没有电脑     | exe / py / 独立客户端全部出局                   |
| 朋友用 iPhone | 自制 APK 出局；App Store 上架（需开发者账号 + 审核）也出局 |
| 要快、要能玩     | 不能引入构建工具、依赖、外部资源、服务器                   |
| 最好有存档      | 必须解决「浏览器不能写本地文件」这个沙盒限制                 |
| 结论         | 单个 `.html` 文件，浏览器直接跑；存档用 JSON          |

### 0.2 v1.0 → v2.0 变更对照

| # | v1.0 写法                                          | 为什么不成立                   | v2.0 结论                                             |
| - | ------------------------------------------------ | ------------------------ | --------------------------------------------------- |
| 1 | 首发 Windows / Mac 独立版，Unity 导出                    | 朋友没有电脑                   | 单文件 HTML5，手机 Safari 为主，桌面浏览器顺带兼容                    |
| 2 | 扩展 iOS / Android（Unity 导出）                       | 打包原生 App 需要开发者账号和电脑      | 网页即 App：Safari「添加到主屏幕」，无需安装                         |
| 3 | 上架 itch.io / Steam，Apple $99/年                   | 完全不需要，也不该花这个钱            | 平台免费在线链接，¥0、免域名、免服务器                                |
| 4 | PlayerPrefs / Settings 读写本地存档                    | 浏览器沙盒不允许网页写本地文件          | `localStorage` 存 JSON 字符串                           |
| 5 | 外部音效文件（bfxr / FL Studio / BGM loop）              | 单文件不能挂外部资源，且 iOS 音频需手势解锁 | Web Audio API 实时合成音效；BGM 移出 MVP                     |
| 6 | 3D 场景、Shader 网格、Bloom、ACES、色差                    | Canvas 里没有后处理管线，手机上也不划算  | Canvas 2D 俯视伪透视 + `shadowBlur` 模拟霓虹                 |
| 7 | PlayerController.cs / Spawner.cs / ObjectPool.cs | C# 工程结构不适用               | 单文件内 IIFE 分模块：Store / Audio / Input / Game / Render |
| 8 | 重力感应倾斜控制                                         | iOS 需额外授权、耗电、不稳，且横竖屏易翻车  | 触摸左右半屏 + 左右滑动手势；键盘仅作桌面兼容                            |
| 9 | 6 天 / 约 23 工时                                    | 单文件无构建、无资源制作             | 按小时计，见第十章                                           |

### 0.3 「html + json」里的 json 到底是什么（重要）

**不会有一个独立的 `.json` 文件生成在磁盘上。** 这是 iOS 浏览器沙盒的硬限制：网页无权写本地文件，只能通过「下载」让用户手动保存。

本文档里 json 指三样东西：

1. **内存里的存档对象**（运行时状态）
2. **`localStorage` 里的一段 JSON 字符串**（真正落盘的存档，浏览器自己管，用户看不见文件）
3. **存档码**：把这段 JSON 编码成一段可复制的纯文本，用于备份、换设备、以及「在线链接」和「本地 html」之间迁移存档

所以「存档」的交付形态是 **一段文本 + 一个自动读写的浏览器存储区**，不是文件。

### 0.4 已确认的决策（v2.0 基础，不变）

- **分发**：在线链接为主（朋友点开即玩）；同时**自留一份本地 `方块冲刺.html`** 作为备份、离线演示与换托管复活的源文件。
- **存档档位**：轻量存档（最高分、累计局数、累计躲避数、设置项）。
- **存档保全**：`localStorage` 自动存 + 一键导出 / 导入 JSON 存档码。
- **费用**：¥0，不买域名、不买服务器、不需要 Apple 开发者账号。

### 0.5 v2.1 玩法策略决策清单（本轮讨论结论）

**诊断**：v2.0 的玩法里，每一帧玩家只有一个正确动作——看见障碍、按左或按右。没有取舍、没有资源、没有「这一步我赌不赌」；难度上升只是压缩反应窗口，玩家不会觉得自己变强，只会觉得手跟不上。同时，纯刷分比的是手速，输的人没有理由再来一局。

| 编号     | 机制                        | 解决什么         | 状态              |
| ------ | ------------------------- | ------------ | --------------- |
| **A**  | 擦边连击 / 风险收益               | 玩法层没决策       | 已定，见 2.5        |
| **E**  | 同种子挑战码                    | 朋友之间没法公平地比   | 已定，见 7.6        |
| **C**  | 波次节奏                      | 每局长得一样、没有记忆点 | 已定，见 2.6        |
| **F1** | 障碍长眼睛                     | 抽象氛围         | 已定，见 6.4        |
| **F2** | 抽象字幕                      | 抽象氛围         | 已定，见 6.4        |
| **F3** | 结算文案随机                    | 抽象氛围         | 已定，见 6.4        |
| **G**  | 假广告浮窗 → 填老梗 → 大转盘 → 纯抽象奖励 | 荒诞感 + 节奏调剂   | 已定，见附录 B        |
| **H**  | MC 风格「实验性玩法」入口（6 个独立开关）   | 用户自留想法       | **已展开，见附录 C**   |
| **I**  | 「高级」按钮 → 警告框 → 单行输入框      | 用户自留想法       | **已展开，见附录 D** |

**未入选**：背景伪代码雨（本轮未选）、旁观者方块、分数自我怀疑。（幽灵方块后来被选进实验性玩法，见附录 C.2；它与 A 的判定冲突在实验局里是故意的。）

> 关键取舍：**不要靠加障碍种类来提趣味**。矮墙、移动块、道具都只是「多一种正确动作」，治不了根。A 是在骨架上动刀，E 是把单人刷分变成可对比的共同关卡，C 是给每局一个能讲给朋友听的段落。

## 一、游戏概述

### 核心玩法

玩家操控一个方块，在一条无限延伸的跑道上自动向前冲刺。通过左右移动躲避迎面而来的障碍物。每避开一个障碍物得基础分，难度随时间和波次提升。一旦碰撞，游戏结束。

**v2.1 新增的核心张力**：贴着障碍擦过去可以累积连击倍率，稳稳换到远处空车道则安全但断连。每个障碍前都要判断一次「值不值得冒险」。

### 平台目标

| 优先级 | 平台              | 打开方式                                |
| --- | --------------- | ----------------------------------- |
| P0  | iPhone Safari   | 微信里点在线链接 → Safari 直接玩；可「添加到主屏幕」全屏启动 |
| P1  | 桌面浏览器 / 其他手机浏览器 | 同一链接或本地 html 双击打开，键盘 ←/→ 或 A/D      |
| P2  | 本地 `file://` 打开 | 作为自己的备份与应急，**不作为对朋友的分发方式**（见附录 A）   |

### 玩家群体（不改）

- 休闲玩家（单局时间短，碎片化游玩）
- 追求极致高分的硬核玩家（难度曲线持续上升 + 倍率滚雪球）

## 二、核心玩法设计

### 2.1 控制方案

| 平台       | 控制方式                     | 备注                    |
| -------- | ------------------------ | --------------------- |
| 手机（主）    | 点屏幕左半区 / 右半区 → 左移 / 右移一格 | 触摸目标区域要足够大，避开刘海与安全区   |
| 手机（主）    | 左右滑动手势 → 对应方向移动一格        | 一次滑动只触发一格，防误连跳        |
| 桌面（兼容）   | ← / A 左移，→ / D 右移        | 空格 = 开始 / 重开          |
| ~~重力感应~~ | 删除                       | iOS 授权 + 耗电 + 不稳，收益为负 |

**所有输入统一走一个 `move(dir)` 入口**，触摸和键盘共用同一套冷却与边界判定。

> **v2.1 约束**：假广告浮窗（附录 B）的填字交互**不得占用左右半屏**，否则会误触切道。浮窗一律用居中弹层 + 候选字块点选。

### 2.2 移动机制（不改）

- **跑道宽度**：3 条车道（左、中、右），MVP 固定 3 条，配置里留 `LANES` 常量可调
- **移动方式**：方案 A —— 按一次，方块**瞬间切换一条车道**（不连续滑动）
- **切换冷却**：0.15 秒，防止单帧内连续跳跃车道作弊闪避
- **边界限制**：方块不能移出最左 / 最右车道
- **视觉缓冲**：用 0.2s 缓出动画做车道间位移，但**逻辑位置立即生效**（避免"看着没过去却算撞了"）

### 2.3 碰撞判定

- 2D AABB 矩形重叠，玩家与障碍物均为正方形
- 碰撞盒收缩至可视大小的 **80%**，减少挫败感
- 碰撞立即触发结算：红色闪烁 + 屏幕震动 + 结算面板
- **擦边判定复用同一套碰撞盒与车道距离**，不新增物理对象（见 2.5）

### 2.4 难度曲线（数值不改，驱动方式改）

| 阶段  | 时间区间    | 速度倍率 | 障碍物间隔（秒） | 最高连续障碍数 |
| --- | ------- | ---- | -------- | ------- |
| 新手期 | 0~15s   | 1.0x | 1.2~1.5  | 1       |
| 舒适期 | 15~45s  | 1.2x | 0.9~1.2  | 1~2     |
| 挑战期 | 45~90s  | 1.5x | 0.7~1.0  | 2~3     |
| 极限期 | 90~150s | 1.8x | 0.5~0.8  | 3~4     |
| 地狱期 | 150s+   | 2.0x | 0.4~0.6  | 3~5     |

> 速度倍率指障碍物朝玩家逼近的相对速度。  
> **实现约束**：阶段判定用累计游戏时间 `elapsed += dt`，**不能用帧数**。iOS 低电量模式、后台切回都会让 `requestAnimationFrame` 降频或停摆，用帧数会导致难度错乱。  
> **v2.1**：难度变成**双轴**——系统给的「速度 × 波次」+ 玩家自己选的「倍率风险档位」。高手不是手更快，是敢一直贴着跑。

### 2.5 擦边连击 / 风险收益（A，核心新增）

**判定**：障碍通过玩家所在 Y 平面时，若玩家车道与该障碍**相邻**（相隔 1 条车道）且未发生碰撞 → 判「擦边成功」，`combo++`。

| 规则   | 内容                                                   |
| ---- | ---------------------------------------------------- |
| 生效范围 | **只对单块障碍生效**；双块不计擦边——躲双块只剩一条活路，没有「贴不贴」的选择空间，计了等于白送倍率 |
| 距离定义 | 用车道数（相邻 = 1），**不按像素阈值**，避免不同屏宽下手感漂移                  |
| 断连   | 换到距离 ≥ 2 的远车道 → `combo = 0`；擦边成功保持连击                 |
| 系统暂停 | 切后台、暂停、假广告浮窗 **一律不断连**（不是玩家失误）                       |
| 死亡   | 直接进结算，倍率不再有意义                                        |

**倍率档位**（每 3 次擦边升一档，封顶 ×4）：

| combo | 倍率 |
| ----- | -- |
| 0~2   | ×1 |
| 3~5   | ×2 |
| 6~9   | ×3 |
| 10+   | ×4 |

**计分**：每躲过一个障碍得 `1 × 当前倍率` 分。倍率影响后续所有得分，形成「越敢贴越滚雪球」；断连的代价是之后所有障碍重新按 ×1 计。

**UI**：HUD 显示当前 `×N` 和一条 combo 进度条（还差几次升档）；擦边瞬间给短闪光 + 火花粒子 + 音效。倍率必须**始终可读**，不能被抽象字幕盖住。

**调参风险**：擦边判定带太宽会变成「随便都算」，太窄变成拼运气。用车道数而非像素，就是为了先避开这个坑。

### 2.6 波次节奏（C）

每 **20~30 秒**一个波次，波次主题顺序由**种子**决定（见 7.6），波间给 **1.5 秒喘息**（无障碍、网格继续滚）。

| 波  | 主题   | 内容               | 与 A 的关系           |
| -- | ---- | ---------------- | ----------------- |
| 1  | 单块雨  | 只出单块，间隔较大        | 教学期，给足擦边练习机会      |
| 2  | 双块墙  | 双块为主，留一条缝        | 不计擦边，逼精确切道，连击自然会断 |
| 3  | 三连窄缝 | 连续 3 组单块，间隔短     | 高风险高倍率段           |
| 4  | 高速直线 | 速度倍率临时 ×1.3，障碍稀疏 | 反应窗口小，贴边更难        |
| 5+ | 混合   | 按难度曲线随机组合        | —                 |

- 波末若**本波无断连**，给「完美通过」反馈（音效 + 顶部短提示）
- 波次编号显示在 HUD 角落，方便朋友之间聊「第 3 波那个窄缝你过没过」
- 波次不改变 2.4 的速度倍率表，只是叠加生成模式与临时修正

## 三、游戏对象设计

### 3.1 玩家方块

| 属性 | 值                                   |
| -- | ----------------------------------- |
| 尺寸 | 车道宽度的 1/3（占满一个车道）                   |
| 颜色 | 霓虹青 `#00FFE5`，`ctx.shadowBlur` 轻微发光 |
| 动效 | 切道时 0.2s 缓出位移 + 轻微弹跳                |

### 3.2 障碍物类型

| 类型    | 形状    | 颜色        | 说明         | MVP | 出现概率 |
| ----- | ----- | --------- | ---------- | --- | ---- |
| 方块    | 正方形   | `#FF3355` | 单车道阻挡      | 是   | 50%  |
| 双块（横） | 2 个并排 | `#FF8800` | 覆盖相邻 2 车道  | 是   | 25%  |
| 矮墙    | 横向矩形  | `#AA44FF` | 覆盖所有车道，需跳跃 | 否   | 15%  |
| 移动块   | 左右横移  | `#FFCC00` | 在一个车道内摆动   | 否   | 10%  |

> **MVP 只做方块 + 双块**（概率归一化为 2:1，波次会临时覆盖分布）。矮墙在纯左右操作下无解，必须配套「上滑跳跃」手势，一起移到第八章拓展。移动块同样移出 MVP。

### 3.3 跑道与背景（3D → 2D 伪透视）

| 元素  | v2.0 实现                           |
| --- | --------------------------------- |
| 视角  | 俯视伪 3D：三条竖直车道，上端略收窄形成透视感          |
| 跑道  | 深灰紫 `#1A1A2E`，半透明网格线              |
| 背景  | 纯黑 `#0A0A0F`                      |
| 速度感 | 网格横线从上向下滚动，滚动速度随难度倍率变化            |
| 侧边  | 两侧霓虹灯条，颜色随机循环 RGB                 |
| 远景  | 竖向流星线 + 少量粒子向两侧飘散（替代原「星空粒子沿 Z 轴」） |

### 3.4 得分与 UI（v2.1 改）

- 屏幕正上方大字号**当前分数**（白色 + 霓虹阴影）
- 分数右侧显示**当前倍率 `×N`** 与 combo 进度条（2.5）
- 分数下方小一号灰字「最高：xxx」（来自 `localStorage`）
- HUD 角落显示**波次编号**（2.6）
- 结算页额外显示**挑战码**（7.6），一键复制
- HUD 用 DOM 覆盖层，不画进 Canvas（省重绘、便于适配安全区）
- **可读性红线**：抽象字幕、浮窗、粒子都不得遮挡分数、倍率、combo 条

## 四、游戏流程与状态机（v2.1 改为五态）

```
menu ──开始──► playing ──碰撞──► over ──再来一次──► playing
                  │  ▲                  └──返回菜单──► menu
       切后台/暂停 ▼  │ 继续
                 paused
                  │  ▲
      adTimer 到点 ▼  │ 关闭 + 0.8s 缓冲
                adPaused
```

| 状态         | 说明                                          | `elapsed` |
| ---------- | ------------------------------------------- | --------- |
| `menu`     | 标题、历史最高分、操作提示、设置、存档码、挑战码导入、H / I 入口         | 冻结        |
| `playing`  | 主循环：位置、生成、碰撞、擦边、计分、波次                       | 累加        |
| `paused`   | 用户主动暂停或切后台（`visibilitychange` / `pagehide`） | 冻结        |
| `adPaused` | 假广告浮窗链路（填字 → 转盘 → 结果），见附录 B                 | 冻结        |
| `over`     | 结算：本局得分、最高倍率、波次、是否新纪录、挑战码                   | 冻结        |

**`adPaused` 硬性规则**（否则会害死人）：

1. 弹出即冻结 `elapsed` 和全部障碍位置
2. **关闭后不立刻恢复**，给 **0.8 秒缓冲**（`bufferTimer`），期间无敌、障碍不动、屏幕显示倒数；否则跟 iOS 后台切回一样，玩家还在看弹窗就被撞死
3. **浮窗期间 `combo` 不断**（系统暂停不是玩家失误，断了会让人不敢点）
4. 恢复后 `adTimer` 重新计时，不补偿暂停期间的时间

**从后台回来必须先暂停，等玩家点「继续」再跑。** v2.0 已定，v2.1 同样适用于 `adPaused`。

### 4.1 开始画面（v2.1 新增两个占位入口）

| 元素                                 | 状态                                                                                                         |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 标题「方块冲刺」+ 副标题「点一下开始」+ 历史最高分 + 操作提示 | 已有                                                                                                         |
| 设置 / 存档码 / 挑战码导入                   | 已有                                                                                                         |
| **「实验性玩法」入口（H）**                   | MC 风格：开始界面一组 **6 个独立复选框 + 警告确认框**，默认全关。只借用 MC 的「藏在开始流程 / 带警告 / 开启后本局不可关 / 与正常玩法隔离」机制，**视觉沿用霓虹风**。完整规格见附录 C |

- 方块自动前进，障碍按**种子驱动的波次生成器**从前方逼近

### 4.3 结算画面

## 五、音效与音乐

### 5.1 音效清单（全部用 Web Audio 振荡器合成，零外部文件）

| 触发场景          | 合成方式               | MVP          |
| ------------- | ------------------ | ------------ |
| 切换车道          | 短促方波「嘀」，40ms       | 是            |
| **擦边成功**      | 上扬短音，音高随 combo 递增  | 是            |
| **倍率升档**      | 两音上行提示             | 是            |
| **波次「完美通过」**  | 三音短句               | 是            |
| **填字正确 / 错误** | 清脆「叮」/ 低沉「咚」       | 是            |
| **大转盘**       | 连续递减间隔的滴答声 + 停顿时重音 | 是            |
| 碰撞死亡          | 噪声爆发 + 低频下滑音       | 是            |
| 新纪录           | 上升三音阶              | 是            |
| 加速阶段切换        | 低沉「嗡」声             | 是            |
| 成功躲避          | 极细微「嗖」声            | 否（建议不加，避免疲劳） |

### 5.2 iOS Safari 音频两个硬坑

1. **必须用户手势解锁**：`AudioContext` 在页面加载时是 `suspended`，必须在**首次 touch/click 的同步回调里** `resume()`。所以「点一下开始」这个动作既开游戏又解锁音频，不能省。
2. **侧边静音键会静音 Web Audio**：这是 iOS 系统行为，网页无解。UI 上不承诺「一定有声音」，音效关掉后游戏完全可玩。

### 5.3 BGM

v1.0 的「BPM 随阶段从 100 升到 150 的合成器 loop」**移出 MVP**，放入拓展。理由：单文件里做可变 BPM 的循环合成会明显增加代码量与耗电，且受上一条静音键影响，投入产出比低。先做纯音效版本。

## 七、数据与持久化（重点章）

### 7.1 存档结构（轻量档，v2.1 加了两个 bool）

`localStorage` key：`fkcc.save.v1`

```json
{
  "v": 1,
  "highScore": 0,
  "totalGames": 0,
  "totalDodged": 0,
  "settings": {
    "sfx": true,
    "shake": true,
    "theme": "neon",
    "abstractFx": true,
    "fakeAd": true
  }
}
```

| 字段                    | 类型     | 默认       | 说明                  |
| --------------------- | ------ | -------- | ------------------- |
| `v`                   | int    | 1        | 存档格式版本，将来加字段时用于兼容迁移 |
| `highScore`           | int    | 0        | 历史最高分               |
| `totalGames`          | int    | 0        | 累计游玩局数              |
| `totalDodged`         | int    | 0        | 累计躲避障碍数             |
| `settings.sfx`        | bool   | true     | 音效开关                |
| `settings.shake`      | bool   | true     | 震动动效开关              |
| `settings.theme`      | string | `"neon"` | 配色主题（预留）            |
| `settings.abstractFx` | bool   | **true** | 抽象元素总开关（6.4），默认打开   |
| `settings.fakeAd`     | bool   | **true** | 假广告浮窗开关（附录 B），默认打开  |

> 仍是 5 个设置项，**没有引入解锁 / 金币 / 战绩列表**，轻量档未被破坏。抽象奖励（G）**不进存档**，只在菜单和结算显示。  
> 字段全为 ASCII，可直接 `btoa` / `atob`；将来若引入中文字段，必须先做 UTF-8 编码再 base64，否则乱码。

### 7.2 写入策略

- **结算面板弹出时写一次**（`totalGames++`、`totalDodged += 本局`、`highScore = max`）
- **实验局例外**：`totalGames` / `totalDodged` 照常累加（玩过一局是事实），但**跳过 `highScore` 写入**，也不生成挑战码。实验局分数纯表演，不污染存档（附录 C.1）
- **设置项改动时立即写**
- 不要每帧写 `localStorage`，同步 IO 会掉帧
- 全程 `try/catch`：iOS 无痕模式、存储已满、`file://` 限制都可能抛异常。异常时**降级为内存存档 + 提示用存档码备份**，游戏绝不能因此崩溃

### 7.3 存档码（导出 / 导入）

格式：`FKCC1:` + `base64(JSON字符串)`

- **导出**：把存档显示在一个可选中的文本框里，配「复制」按钮（`navigator.clipboard` 在 `file://` 下可能不可用，必须提供长按手动复制的兜底）
- **导入**：粘贴 → 校验 `FKCC1:` 前缀 → `atob` → `JSON.parse` → 校验 `v` 与字段类型 → **弹二次确认，显示两边最高分对比** → 覆盖
- 校验失败只提示，不覆盖现有存档
- 用途：清 Safari 数据后恢复、换手机、以及下面 7.4 的跨环境迁移
- **与挑战码分流**：挑战码前缀是 `FKCC-Q1:`，导入入口按前缀识别，两者互不干扰

### 7.4 两个环境，两套存档（必须写清楚）

| 环境                 | origin            | 存档位置                  | 可靠性                      |
| ------------------ | ----------------- | --------------------- | ------------------------ |
| 在线链接（HTTPS）        | 平台域名              | 该域名下的 `localStorage`  | 高，但清浏览器数据 / 无痕模式 / 换设备会丢 |
| 本地 html（`file://`） | 通常为 `null` 或逐文件隔离 | iOS Safari 上常被禁用或随时清空 | **不可靠**                  |

**两边的 `localStorage` 不共享。** 存档码是唯一能在两者之间搬存档的手段。

### 7.5 运行时数据（不落盘）

| 字段               | 类型         | 说明                             |
| ---------------- | ---------- | ------------------------------ |
| `score`          | int        | 当前分数                           |
| `elapsed`        | float      | 累计游戏时间（毫秒），驱动难度曲线与波次；**暂停时冻结** |
| `currentSpeed`   | float      | 当前速度倍率                         |
| `spawnTimer`     | float      | 障碍物生成倒计时                       |
| `lane`           | int        | 当前车道 0/1/2                     |
| `lastMoveAt`     | float      | 上次切道时间，用于 0.15s 冷却             |
| `combo`          | int        | 当前连击数（2.5）                     |
| `multiplier`     | int        | 当前倍率 1~4                       |
| `bestMultiplier` | int        | 本局最高倍率，结算显示                    |
| `waveIndex`      | int        | 当前波次编号（2.6）                    |
| `waveTimer`      | float      | 波次剩余时间                         |
| `seed`           | int        | 本局随机种子（7.6）                    |
| `challengeSeed`  | int / null | 若由挑战码导入，记录挑战者的种子               |
| `adTimer`        | float      | 距下次假广告浮窗的 `elapsed` 倒计时        |
| `adCount`        | int        | 本局已弹浮窗次数                       |
| `bufferTimer`    | float      | 浮窗关闭后的 0.8s 恢复缓冲               |

`lives` / 多命模式删除，不在轻量档内。

### 7.6 同种子挑战码（E，核心新增）

**目标**：把「我 37 分你敢不敢试」变成「同一串障碍你过不过得了第 3 波」。零后端、零联网、零存档结构改动。

**地基要求（必须早做）**：生成器换成**可复现的种子随机**，`Math.random()` 在障碍生成链路里**全面禁用**。用 mulberry32 / xorshift32 这类 32 位 PRNG，`seed` 为整数。

- 障碍类型、车道、间隔抖动、波次主题顺序，**全部走同一个主 PRNG 实例**
- **装饰性随机必须走独立 PRNG 实例**（抽象字幕抽哪句、结算文案抽哪句、粒子位置、转盘结果）。理由：**设置开关不得影响障碍序列**。否则 A 开了抽象元素、B 没开，两人用同一个挑战码却跑出不同障碍，公平性直接崩
- 假广告浮窗的 70/30 判定同样用独立随机源

**挑战码格式**：`FKCC-Q1:` + `base36(seed)` + `-` + `base36(score)`，例 `FKCC-Q1:3K7Z9-1F`

**导入流程**：菜单「挑战好友」→ 粘贴挑战码 → 校验前缀 / 解析 → 用该 `seed` 开局 → HUD 角落显示「挑战：1F 分」→ 结算显示「挑战者 1F / 你 2C」+ 胜负文案。

**公平性约束（写死，不许破）**：

1. 奖励**不得给数值**（已定为纯抽象奖励，见附录 B）——否则同一串障碍有人多一条命
2. 设置项（`abstractFx` / `fakeAd` / `sfx` / `shake`）**不得影响障碍序列**
3. 暂停、切后台、浮窗期间**不计入 `elapsed`**，也不推进生成器
4. 挑战码只锁障碍序列，不锁玩家操作与倍率选择——这正是可比的部分
5. **实验局整局禁用**：任意实验开关开启时，结算不生成挑战码、菜单导入入口灰掉。实验玩法改了车道数 / 擦边判定 / 输入映射，同种子也无法复现同一局（附录 C.1）

### 7.7 假广告与转盘的随机数据（G）

| 项      | 界面显示                   | 实际判定                |
| ------ | ---------------------- | ------------------- |
| 大转盘成功率 | **0.1% 成功 / 99.9% 失败** | **70% 成功 / 30% 失败** |

> 反差点：界面吓唬人，实际很大方。显示的数字只是文案，**不参与任何计算**。  
> 填字题目、候选字、抽象奖励文案都从内置词库抽，词库直接写在单文件 HTML 的 `CONFIG` 里，不请求外部资源。

## 九、技术实现要点（HTML5 版）

### 9.1 交付物结构

```
方块冲刺/
├── 方块冲刺.html               ← 唯一程序文件，零外部请求
└── 方块冲刺-游戏详细设计.md    ← 本文档
```

`方块冲刺.html` 内部：

```html
<meta> / <style>          全屏、安全区、禁滚动缩放、DOM UI 层
<canvas id="game">         跑道 / 方块 / 障碍 / 眼睛 / 粒子
<div id="ui">              菜单 / HUD / 暂停 / 结算 / 设置 / 存档码 / 挑战码
<div id="adLayer">         假广告浮窗 / 填字 / 大转盘 / 缓冲倒数
<script> (IIFE)
  ├─ CONFIG               难度曲线、配色、车道数、冷却、倍率表、波次表、老梗词库
  ├─ PRNG                 主实例(障碍序列) + 装饰实例(字幕/粒子/转盘)，严格分离
  ├─ Store                localStorage、存档码、挑战码编解码、异常降级
  ├─ Audio                Web Audio 合成音效 + 首次手势解锁
  ├─ Input                touch / keyboard → 统一 move(dir)
  ├─ Waves                波次调度、主题、喘息、完美通过判定
  ├─ Ad                   浮窗触发、填字、转盘、抽象奖励、恢复缓冲
  ├─ Game                 五态状态机、主循环、对象池、擦边判定、碰撞、计分
  └─ Render               Canvas 2D 分层绘制 + 抽象元素开关
</script>
```

**零外部请求**：不引 CDN、不引字体、不引图片、不引音频。保证本地 `file://` 打开也能完整运行。

### 9.2 主循环

```js
let last = performance.now();
function loop(now) {
  const dt = Math.min(now - last, 50);  // 上限，防后台回来大跳
  last = now;
  if (state === 'playing') {
    if (bufferTimer > 0) { bufferTimer -= dt; }  // 浮窗恢复缓冲，期间无敌
    else { update(dt); }                        // elapsed += dt
  }
  render();
  requestAnimationFrame(loop);
}
```

`dt` 上限是关键：iOS 从后台恢复时第一帧可能是几秒，不限幅会瞬间生成一堆障碍并直接判定死亡。`paused` / `adPaused` / `menu` / `over` 一律不调用 `update()`，`elapsed` 天然冻结。

### 9.3 iOS Safari 适配清单

| #  | 项             | 做法                                                                                                       |
| -- | ------------- | -------------------------------------------------------------------------------------------------------- |
| 1  | viewport      | `width=device-width, initial-scale=1, viewport-fit=cover, user-scalable=no`                              |
| 2  | 禁止滚动 / 橡皮筋    | `touch-action: none`、`overscroll-behavior: none`，`touchmove` 用 `{ passive: false }` 并 `preventDefault()` |
| 3  | 刘海 / 底部横条     | `env(safe-area-inset-top/bottom)` 留白，按钮别贴边；抽象字幕放在底部安全区**上方**                                             |
| 4  | 高清屏不糊         | `canvas.width = cssW * devicePixelRatio`，再 `ctx.scale(dpr, dpr)`                                         |
| 5  | 禁止双击缩放 / 长按选中 | `user-select: none`、`-webkit-touch-callout: none`；**存档码 / 挑战码文本框要单独放开可选中**                               |
| 6  | 添加到主屏幕        | `apple-mobile-web-app-capable`、`apple-mobile-web-app-status-bar-style`                                   |
| 7  | 后台切回          | `visibilitychange` / `pagehide` → 自动进 `paused`                                                           |
| 8  | 音频解锁          | 首次触摸同步回调里 `audioCtx.resume()`                                                                            |
| 9  | 无痕模式          | `localStorage` 全包 `try/catch`，降级内存 + 提示存档码                                                               |
| 10 | 帧率波动          | 一切位移乘 `dt`，禁止「每帧 +1」写法                                                                                   |
| 11 | **填字不弹软键盘**   | 用候选字块点选；「高级」单行输入框（I）才用真 `<input>`，需处理软键盘挤压布局                                                             |
| 12 | **浮窗不误触切道**   | `adLayer` 覆盖时，左右半屏的 touch 监听临时挂起，只响应弹层内部                                                                 |
| 13 | **浮窗恢复缓冲**    | 关闭后进 0.8s `bufferTimer`，期间无敌、障碍冻结、显示倒数                                                                   |
| 14 | **计时口径统一**    | `adTimer` / `waveTimer` 全部用 `elapsed`（暂停冻结），**不用墙钟时间**                                                   |

### 9.4 性能

- 障碍物用**对象池**（数组 + `active` 标记），不反复创建销毁，减少 GC
- `shadowBlur` 只给玩家和障碍物，**不要全屏开**
- 粒子数量上限 60
- 一帧分层：清屏 → 滚动网格 → 车道线 → 障碍 → 障碍眼睛(F1) → 粒子 → 玩家 → 发光
- HUD / 抽象字幕 / 浮窗用 DOM，不进 Canvas 重绘
- F1 眼睛是每障碍 2 个 `arc`，开销可忽略；开/关不重建对象池
- 生成基于**时间倒计时**，不基于帧计数

### 9.5 桌面兼容

同一份 html 双击打开即可用键盘玩；用 `window.innerWidth/innerHeight` 自适应画布，手机上竖屏铺满、桌面上限制最大宽度居中，不改代码。

## 附录 B：假广告浮窗完整链路（G）

### B.1 触发

| 项  | 规则                                                 |
| -- | -------------------------------------------------- |
| 计时 | `adTimer` 按局内 `elapsed` 倒计时，**暂停 / 切后台 / 浮窗期间不累加** |
| 频率 | 每 **25~40 秒**随机一次（原「1~2 分钟」按多数休闲玩家活不到 1 分钟调整过）     |
| 上限 | 每局最多 **2 次**，防止长局刷屏                                |
| 前置 | `settings.fakeAd === true`，且当前状态为 `playing`        |
| 弹出 | 立刻进 `adPaused`，冻结 `elapsed` 与全部障碍；左右半屏触摸监听挂起       |

### B.2 浮窗 → 填字

- 浮窗文案故意写得很俗，随机一条：**「广告获得 神秘称号 ×1」「广告获得 稀有边框」「广告获得 限定气泡」**
- **点击后不播广告**，直接弹填字题
- 题目：随机一句老梗，挖掉几个字；给 **3~4 个候选字块点选**（不弹软键盘）
  - 例：「真相只有\_\_」→ `一个` / `两只` / `三分` / `没有`
  - 例：「确认过\_\_」→ `眼神` / `天气` / `菜单` / `余额`
  - 例：「蓝瘦\_\_」→ `香菇` / `排骨` / `青菜` / `可乐`
- 答对 → 进入大转盘；答错 → 提示重选，**最多 2 次机会**
- 两次都错 / 主动关闭 → 浮窗消失，**不扣任何东西**，本周期不再出现

### B.3 大转盘

| 项    | 内容                                                 |
| ---- | -------------------------------------------------- |
| 界面显示 | **成功率 0.1% · 失败率 99.9%**（纯文案，吓唬人，不参与计算）            |
| 实际判定 | **70% 成功 / 30% 失败**（独立随机源，不碰障碍序列 PRNG）             |
| 动画   | CSS `transform: rotate` 缓出 1.5~2s + 递减间隔滴答声，停在对应扇区 |
| 成功   | 给一个**纯抽象奖励**：随机称号或一句评语，显示在菜单/结算，无数值效果、不进存档         |
| 失败   | 一句安慰梗（「广告没白看，但也没给」之类），无奖励                          |
| 关闭   | 进 **0.8 秒恢复缓冲**：无敌、障碍冻结、屏幕倒数；缓冲结束才回 `playing`      |

### B.4 为什么奖励必须是纯抽象的

如果给加分或免死，7.6 的同种子挑战码就不公平了：同一串障碍，有人多一条命。整条链路本来就是反讽「看广告得奖励」，真给数值反而俗了，还污染核心玩法。设置里 `fakeAd` 可以整体关掉。

### B.5 状态与 combo

浮窗期间 `combo` **保持不清零**（2.5 / 四章）。系统暂停不是玩家失误，断了会让人不敢点浮窗，这个功能就废了。

## 附录 C：实验性玩法完整规格（H）

### C.1 定位与四条铁律

参照 Minecraft 新建世界流程里的 Experiments：**藏在开始界面、带醒目警告、开启后本局不可关、与正常玩法严格隔离**。只借机制，**不做 MC 视觉**——沿用 6.1 的霓虹配色与版式。

| # | 铁律                                                         | 理由                                           |
| - | ---------------------------------------------------------- | -------------------------------------------- |
| 1 | **每局开局前勾选，默认全关，不写 `localStorage`**                         | 轻量存档一个字段都不加；下局自动恢复默认关                        |
| 2 | **开局读一次写入运行时 flags，本局锁死不可关**                               | 复刻 MC「开启后无法关闭」；实现上不用支持运行中动态切换                |
| 3 | **任意实验开关开启 → 本局禁用挑战码**（结算不生成、菜单导入灰掉）                       | 实验改了车道数 / 判定 / 输入，7.6 的「同一串障碍 + 同一套规则」前提不再成立 |
| 4 | **实验局跳过 `highScore` 写入**；`totalGames` / `totalDodged` 照常累加 | 分数是表演道具，不该污染纪录；玩过一局是事实                       |

**警告框文案（示例）**：

> **实验性玩法**  
> 这些功能还在测试中，可能导致分数看起来很奇怪、方块做出不符合物理的事，以及你怀疑自己是不是按反了。  
> 本局成绩不会记入最高分，也不能生成挑战码。**开启后本局无法关闭。**

> 与 I（高级按钮）的警告框是**两个不同的弹窗**，文案和后续流程都不同，实现时别复用同一个组件。

### C.2 六个独立开关

菜单里是六个复选框，可任意组合；**任意组合都必须能跑，不保证好玩**。

| # | 开关       | 效果                                                    | 改动点                       | 来源   |
| - | -------- | ----------------------------------------------------- | ------------------------- | ---- |
| 1 | **重力翻转** | 按左往右、按右往左，滑动手势一起反；边界限制照常                              | 只翻 `move(dir)` 的 `dir` 符号 | 用户提  |
| 2 | **分数乱动** | 游戏中数字抖动 / 短暂变乱码，**真实 `score` 不动**；结算显示相反数 + 连点彩蛋（C.4） | 显示层 + 结算贴纸组件              | 用户提  |
| 3 | **恐怖画风** | 四元素全上（C.5）                                            | 背景覆盖层 + Web Audio         | 用户提  |
| 4 | **幽灵方块** | 一条车道上有个永不碰撞、半透明、固定节奏移动的方块                             | 只加绘制，不进对象池的碰撞 / 擦边链路      | 本轮补充 |
| 5 | **四车道**  | `LANES=4`，跑道与方块宽度重算                                   | 车道布局 + 波次表                | 本轮补充 |
| 6 | **倒车模式** | 障碍从屏幕下方往上走、网格反向滚                                      | 生成位置 / 速度符号 / 网格方向取反      | 本轮补充 |

**结算彩蛋归属**：相反数 + 连点 5 下贴纸崩掉，归入「分数乱动」这一项，不单列开关。若你想让它独立成一个开关，改菜单一行即可。

### C.3 冲突矩阵（实现前必读）

| 组合                       | 问题                                       | 处理                                                                                |
| ------------------------ | ---------------------------------------- | --------------------------------------------------------------------------------- |
| **四车道 × A 擦边**           | 2.5 的判定是「相邻车道 = 距离 1，双块不计擦边」，车道数变了会不会失效？ | **规则不变**。相邻仍按车道数算，双块仍不计擦边。四车道下双块留 2 条空道，玩家有「近空道 / 远空道」可选，贴边机会自然减少，属于难度变化不是 bug    |
| **幽灵方块 × A 擦边 / 6.4 红线** | 长得像障碍，会误导玩家判断哪个能擦                        | **故意的**——混乱就是实验局的目的。但幽灵方块**不参与碰撞、不计擦边、不产生任何游戏状态**，只绘制。它是实验玩法，不受 6.4「抽象元素不碰判定」红线约束 |
| **倒车 × 波次 / 擦边判定**       | Y 轴方向反了，生成和判定会不会跟着错                      | 擦边判定仍以「障碍通过玩家 Y 平面」为准，**与方向无关**；波次调度、`elapsed`、难度曲线全不动，只取反生成位置与速度符号               |
| **重力翻转 × 操作提示**          | 菜单写了「点左半屏左移」，实际反了                        | **提示故意不改**，制造「是不是按反了」的困惑（警告文案里已预告）。边界限制照常生效                                       |
| **恐怖画风 × HUD 可读性**       | 暗角 / 扫描线 / 血字可能盖住分数与倍率条                  | **层级写死**：恐怖覆盖层在 Canvas 背景之下，HUD / 抽象字幕 / combo 条在最上层。扫描线不得覆盖任何读数                  |
| **分数乱动 × 7.2 写入**        | 显示的是假数字，写进存档会有认知冲突                       | 真实 `score` 全程不动；实验局跳过 `highScore`，`totalGames` / `totalDodged` 照常累加               |
| **任意开关组合**               | 六个全开会非常混乱                                | 每个 flag 独立分支，**不写互斥逻辑**；只保证不崩溃，不保证平衡                                              |

### C.4 结算贴纸彩蛋流程（「分数乱动」专属）

```
over（实验局，且开了「分数乱动」）
  → 分数区显示 -score（真实分数的相反数），带平面「贴纸」质感
  → 只在点分数贴纸本身时计数；5 下须在 2 秒内连完
  → 第 5 下：贴纸碎裂剥落
  → 露出真实得分（一次性揭底，之后不可再变回相反数）
  → 「再来一次」/「返回主菜单」按钮区不计入连点
  → 不写 highScore、不生成挑战码
```

| 项    | 规则                                                                                     |
| ---- | -------------------------------------------------------------------------------------- |
| 真实分数 | **整个实验局里唯一露脸的机会**就是贴纸崩掉这一下，所以揭底感是这个彩蛋的核心                                               |
| 触发区域 | 只点分数贴纸本身；点背景、点按钮都不计数，避免误触                                                              |
| 时限   | 5 下在 2 秒内连完；超时计数清零重新算，防止慢慢点也触发                                                         |
| 动画实现 | CSS `clip-path` 分块 + `transform` / `opacity` 做碎片剥落；**禁用 `filter` / `blur`**，iPhone 上不卡 |
| 可重复  | 崩掉后保持显示真实分，不再变回相反数；重开新局重新计算                                                            |

### C.5 恐怖画风四元素（全上）

## 附录 D：高级输入框与命令系统（I）

> 本附录为 **v2.4 唯一权威规格**。正文 4.1 / 八章 / 十二章里关于 I 的早期占位表述，一律以本附录为准。

### D.1 入口与提交流程

- 开始界面一个独立「高级」按钮，**与 H 的实验性玩法入口是两个不同入口**，不合并
- 点击 → 警告确认框「确定要进入吗？」→ 进入高级面板
- 面板：一个**很普通的单行输入框** + 页面上的**实体 Enter 按钮**（不依赖软键盘回车）
- 提交后依次：屏幕颤动动画 → 屏幕一黑 **1~2 秒** → 显示反馈文案

**反馈文案按你的原文保留，语法不动**：

```
XXX is turn on,and you can XXX.
```

- 第一个 `XXX` = 命令 / 模式名；第二个 `XXX` = 一句功能描述。例：`dev is turn on,and you can edit score.`
- 你原文里的「输下去·」，那个 `·` 视为分隔符笔误，**不是要输入的字符**
- 输错 / 不认识的命令：黑屏后显示 `unknown command`，**不颤动、不改任何状态**
- 黑屏期间若切后台，按第四章 `visibilitychange` 处理，回来先进暂停

### D.2 作用域与四条铁律

| # | 铁律 | 说明 |
|---|------|------|
| 1 | **效果只在本次页面会话有效，刷新即恢复** | 不写 `localStorage`，轻量存档一个字段都不加；命令状态存内存对象 |
| 2 | **url 定时任务与页面生命周期绑定** | 关掉高级面板不影响任务；**关闭网页才取消**（与「除非关闭网页，不然到点执行」一致） |
| 3 | **任意 I 命令生效期间隔离纪录** | 本局不生成挑战码、跳过 `highScore` 写入；`totalGames` / `totalDodged` 照常累加。**对 7.2 与 7.6 第 5 条的补充**：`type on` 能改分数、`get from enter` 换了游戏目标，不隔离会污染纪录 / 让挑战码失去可比性 |
| 4 | **密码固定 `devczy`** | `CONFIG.DEV_PASSWORD = 'devczy'`，`type on` / `type off` 都要带 |

> **直白提醒**：密码写在前端单文件里，任何人「查看源码」都能看到 `devczy`。这是防误触，不是真安全。你选了「只读源码 + 可执行控制台 + 复制」，等于把这条也公开了。

### D.3 命令表

| 命令 | 效果 | 状态 |
|------|------|------|
| `get from enter` | 开启**出口模式**：目标从「刷多少分」变成「走出出口」，门槛 100→500→1000→… 递进 | **已定，完整规格见 D.8** |

| `get into dev` | 开发者模式·阉割版 B：调试信息 **+ 控制生成** | 已定 |

| `type off <password>` | 关闭开发者模式 | 已定 |

**percent 规则**：`num` 是 **0~100 整数**。按固定功能清单 `FUNCTIONS[]` 的顺序保留前 num% 项，其余功能**关闭但入口保留**；玩家点进被关闭的入口 → 显示 **404 页**（一个 DOM 弹层）。例 `percent40` = 保留清单前 40%。可复现、好调试。

- 被关闭的入口不隐藏，正是为了触发 404 这个反馈
- 「设置」「返回菜单」「高级」等基础入口建议列入白名单，避免玩家把自己卡死

### D.4 完整开发者模式权限（`type on devczy`）

|------|------|

**代码源码仅支持 Windows**：

### D.5 浏览器硬约束与兜底

| 约束 | 处理 |
|------|------|
| **延迟跳转会被弹窗拦截** | 你选了「直接跳转」，所以先尝试 `window.open`；**若返回 null / 被拦截，自动降级**为弹一个提示框 + 「打开」按钮，玩家点一下才跳。iOS Safari 必拦，桌面 Chrome / Firefox 也可能拦。这样「直接跳转」的意图保留，功能不会静默消失 |

### D.8 出口实验功能（`get from enter`）· 已定

**你给的定义**：开启后，方块的目标从「刷多少分」变成「**走出出口**」；出口按分数门槛递进出现——**100 分 → 500 分 → 1000 分 → ……**

这是唯一一个**改变胜利条件**的模式：其余玩法都在无限跑酷里比分数，出口模式给了阶段目标。撞到障碍依然游戏结束，它不是无敌模式。

#### D.8.1 门槛序列

```
CONFIG.EXIT_THRESHOLDS = [100, 500, 1000, 2000, 4000, 8000, ...]
```

- 前三档按你给的 **100 / 500 / 1000** 写死
- 1000 之后按 **×2** 递增（2000 / 4000 / 8000…），没有终点，符合无限跑酷骨架
- 门槛判定用**真实 `score`**，不受「分数乱动」这类显示层实验影响

#### D.8.2 出口对象与判定

| 项 | 规则 |
|----|------|
| 出口长什么样 | 达到当前门槛时，前方生成一扇**发光门框**，占据一条车道，随障碍一起向玩家逼近 |
| 物理 | **不碰撞、不阻挡、不计擦边**，纯目标物 |
| 怎样算「走出」 | 门框经过玩家 Y 平面时，玩家正处于该车道 → 判定成功 |
| 错过 | 门飘走，**同一门槛每隔 3~5 秒重新生成一次**，直到走出去。不会卡死 |
| 公平窗口 | 门生成前后各 1 秒不生成障碍；门所在车道不放障碍 |
| 通关反馈 | 特效 + 提示（如 `exit 100 cleared`），门槛推进到下一档，游戏继续、分数继续累积 |
| HUD | 显示「当前目标：走出出口」「下一个出口：100 分」，补在分数旁，不遮挡倍率条 |

#### D.8.3 与其它机制的关系

- **A 擦边连击**：照常生效；出口门不参与擦边判定
- **E 挑战码**：出口模式期间**禁用**（D.2 第 3 条）——游戏目标都换了，同种子也没法比
- **H 实验性玩法**：可叠加。若同时开了「分数乱动」，门槛仍按真实分数判定
- **假广告浮窗**：照常触发，仍走 `adPaused` 与 0.8 秒恢复缓冲
- **存档**：不写 `localStorage`，作用域同 D.2（本次页面会话、刷新恢复）
- **实现**：第十章第 12 步包含本模式；`Command` 里加 `ExitMode` 子模块，门框复用对象池但不进碰撞链路

#### D.8.4 出口模式的 8 条默认值（我替你定的，确认时重点看）

1. 门槛前三档 100 / 500 / 1000，之后 **×2** 递增，无终点
2. 出口是一扇**单车道发光门框**，不是全屏传送门
3. 判定为「门经过玩家 Y 平面时玩家在该车道」
4. **错过可在同一门槛重试**（每 3~5 秒再来一次），不推进、不惩罚
5. 门前后各 1 秒不生成障碍，保证能专心对准
6. 门**不碰撞、不计擦边**，出口模式仍可能撞障碍死亡
7. 通关只给特效和提示，**不给数值奖励**（不污染分数）
8. 出口模式期间禁用挑战码、跳过 `highScore`，`totalGames` / `totalDodged` 照常

> 这 8 条里若有一条不合你想的（尤其是「错过可重试」和「×2 递增」），改文档一句话就行，别等写完代码再改。
