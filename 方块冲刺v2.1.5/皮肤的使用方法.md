# 方块冲刺 · 皮肤使用方法（开发者版）

> 版本：v1.6.0
> 源码：`方块冲刺.html`，皮肤段落集中在脚本尾部「v1.6.0 皮肤系统」
> 玩家向说明见《皮肤使用方法-玩家.md》，原始格式见《皮肤的使用方法.txt》

---

## 1. 数据结构

```js
save.skin          // 内置配色 key：'neon' | 'hidden'
save.skinCode      // 玩家导入的原始皮肤代码字符串（null = 未导入）
save.unlockedSkins // { hidden:true } 表示彩蛋已解锁
skinCustom         // 运行时解析结果，不写存档；null = 用 CONFIG.player 画纯色
CONFIG.skins       // 内置配色表
```

`skinCustom` 两种形态：

```js
// normal
{ mode:'normal', color:'#FF3B3B', name:'纯色' }
// pro
{ mode:'pro', w:3, h:2, name:'mine', grid:[
  ['#FF3B3B','#3BD66F','#3B7BFF'],
  ['#FFFFFF','rgb(100,203,102)',null]   // null = 透明格
]}
```

`parseSkinCode(src)` 返回 `{ok, skin, errors}`。`ok=false` 时 `errors` 是字符串数组，每条带「第 N 行」；**整份拒绝，不部分应用**。

---

## 2. 解析器接线

| 函数 | 职责 |
|---|---|
| `stripSkinComment(l)` | 去注释。仅当 `#` 在行首或前一字符是空白时才截断；否则保留为 `#RRGGBB` |
| `parseSkinColor(tok)` | 颜色词 → `{c:'#…'}`；空 → `{transparent:true}`；非法 → `null` |
| `parseSkinCode(src)` | 逐行状态机，产出 `normal` / `pro` 皮肤或错误列表 |
| `applySkin()` | 先套 `CONFIG.skins[save.skin]` 全套配色，再用 `save.skinCode` 覆盖玩家方块皮肤 |
| `resetSkinVisual()` | 删档/恢复默认：回霓虹、清空 `skinCode` 与 `skinCustom` |
| `drawPlayerSkin(x,y,cell)` | `render()` 里调用；返回 `false` 时回落到 `CONFIG.player` 纯色方块 |
| `renderSkinList()` | 渲染皮肤列表（含未解锁的 `???` 占位） |

`SKIN_COLORS` 是十色表：`red orange yellow green cyan blue purple pink white black`。加色只需往这个对象里加一项，玩家文档同步补一行。

## 3. 语法（已与用户确认）

```
size = normal | pro
size.color( <色名> | R,G,B | #RRGGBB )
size.x_y(w,h)                      # w,h ∈ [1,16]
size.pro.<name> = [
[[c],[c],[c]],                    # h 行 × w 列
...
]
use(size.pro.<name>)
```

规则：

- `#` 注释仅识别行首或空白之后。
- `size` 只能声明一次；`size.color` 只能一次。
- `pro` 必须同时具备 `size.x_y`、`size.pro.<name> = [`、`use(...)`，且 `use` 引用的表必须存在。
- 像素表行数必须等于 `h`，每行格子数必须等于 `w`。
- 单个格子：`[]` = 透明（`null`）；色名 / `R,G,B` / `#RRGGBB` = 实色。
- 像素行用 `/\[([^\[\]]*)\]/g` 提取，避免把外层 `[` `]` 当成格子。
- 像素表结束行用 `/^\]\s*[,;]?\s*$/` 识别。
- 未知语句、重复声明、缺结束 `]`、颜色越界（>255）都会报错并带行号。

### 校验策略

**整份拒绝 + 逐条列错**。收集完所有错误再一次性返回，`ok=false` 时不写 `save.skinCode`、不调 `applySkin()`。UI 用 `r.errors.map(x=>'· '+x).join('\n')` 输出。

> 若日后要改格式（例如支持多皮肤层、支持障碍配色），只需替换 `parseSkinCode()` 与 `drawPlayerSkin()`，其余接线（存档、UI、错误区、彩蛋）不用动。

## 4. UI 与存档

- 入口：`setLayer` 的 `#btnSkinSet` → `layer('skinLayer')`。
- 独立界面：`#skinList`（列表）、`#skinInput`（textarea）、`#skinImport` / `#skinReset` / `#skinBack`、`#skinOk` / `#skinErr`。
- 导入成功才 `save.skinCode = …; writeSave(); applySkin()`。
- 「恢复默认」：`save.skin='neon'; save.skinCode=null`，不清解锁状态。
- 极限难度死亡删档：`save` 整体重置为 `DEFAULT_SETTINGS` 派生的新对象，并调 `resetSkinVisual()`；**两处硬编码重置（gameOver 极限分支、setDelete）都要保持这个形状**，否则新字段会丢。

## 5. 彩蛋

```js
$('aboutVer').addEventListener('click', function(){
  var now=Date.now(); if(now-aboutClickT>1800) aboutClicks=0;
  aboutClickT=now; aboutClicks++;
  if(aboutClicks>=5){ ... save.unlockedSkins.hidden=true; writeSave(); ... }
});
```

- 对象是 `#aboutVer`（`.tag`，黄色，`#FFCC00`）。
- 1.8 秒窗口内连点 5 次；超时计数归零。
- 解锁写入 `save.unlockedSkins.hidden`，`renderSkinList()` 据此显示「黄金」。
- 已解锁再点只 `toast('黄金皮肤早已解锁')`。

## 6. 渲染注意点

- `drawPlayerSkin` 在 `ctx.save()` / `restore()` 之间调用，`shadowBlur` 沿用玩家光晕；pro 模式每格 `fillRect(x+c*gw, …, gw+.6, gh+.6)`，加 `.6` 避免相邻格出现亚像素缝。
- 透明格 `continue` 不绘制，露出跑道底色。
- 皮肤**只改玩家方块**；`CONFIG.obs/obs2/bg/grid` 由内置配色控制，两套互不覆盖。
- 切道动画用 `laneVisual` 插值绘制位置，皮肤跟着 `vx` 走；判定框仍画在 `G.lane`，两者分离。
- 恐怖模式下 `render()` 会把障碍染红，玩家皮肤不受影响（设计如此）。

3. 更新《皮肤使用方法-玩家.md》语法表与示例。
4. 更新本文件的数据结构与测试章节。
