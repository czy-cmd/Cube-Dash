## 2. 五级挑战体系（等级码明文）

### 2.1 级别定义（`LEVELS`，约 2176 行）

```js
var LEVELS=[
  {lv:1,need:100, coins:500,  badge:'初露锋芒'},
  {lv:2,need:300, coins:1200, badge:'渐入佳境'},
  {lv:3,need:600, coins:2500, badge:'势不可挡'},
  {lv:4,need:1000,coins:5000, badge:'登峰造极'},
  {lv:5,need:1500,coins:10000,badge:'传说'}
];
```

### 2.2 五段固定等级码 🔴

粘贴到主菜单「挑战好友」开局，结算时显示「你距离该级别还有 XXX 分」；达到 `need` 即授予金币 + 称号 + 专属编码（存档去重，只能领一次）。

| 级别 | 目标分 | 奖励金币 | 称号 | 等级码 |
|------|-------|---------|------|--------|
| 1 | 100 | 500 | 初露锋芒 | `CZYFK2-O14WI3YJQYXAXGI9I4B` |
| 2 | 300 | 1200 | 渐入佳境 | `CZYFK2-O14XI5YJQP94YT8WX95` |
| 3 | 600 | 2500 | 势不可挡 | `CZYFK2-O14YI8YJQCXDETETZOQ` |
| 4 | 1000 | 5000 | 登峰造极 | `CZYFK2-O14ZI3YJRENMZJIF161E` |
| 5 | 1500 | 10000 | 传说 | `CZYFK2-O14.I32JRERL0HYIIOHW` |

> ⚠️ 这 5 段码由 `codeSeal('LV.'+lv+'.'+need)` 生成后写死（`LEVEL_CODES`）。
> **改 `LEVELS` 里的 `need` 会改变码**，必须重新导出并替换这里和上表里的值，否则玩家手里的旧码全部失效。

### 2.3 结算逻辑（`grantLevel()`，约 2215 行）

- `parseLevelCode(t)`：只精确比对 `LEVEL_CODES` 这 5 段；普通挑战码含 `-` 分隔符被排除。
- 结算页：未达标显示「距离该级别还有 N 分」；达标调 `grantLevel(lv)`。
- `grantLevel()`：`save.officialDone[lv]` 去重 → 加金币 → `addBadge(称号)` → `makeCode(lv)` 生成专属编码存 `save.codes[lv]` → 若已登录，同步把金币 / 称号写进该账户 → 写存档。

## 3. 加密与编码机制（密钥）🔴

### 3.1 密钥与算法（约 1528 行）

```js
var CODE_KEY='FKCC-V16-CHALLENGE-2026-czy';
```

- `codeHash(s)`：字符串哈希。
- `codeSeal(plain)`：`plain + '.' + 内层校验(4位)` → 流加密 → 外层校验(6位)，返回 `密文-校验`。
- `codeOpen(cipher, sig)`：先验外层 6 位防篡改，解密后再验内层 4 位防伪造，任一不符返回 null。
- `codeB36(n, len)`：数值转定长 36 进制。
- 挑战码 `CZYFK2-…`、等级码、装逼码 `CZYBB-JX-…`、专属编码 `CZYBD-…` 全部基于这套。

> ⚠️ **改 `CODE_KEY` 会让所有已发出的码（挑战码 / 等级码 / 专属编码 / 装逼码）一次性全部失效**。除非你准备好重新分发，否则绝不要动。

### 3.2 挑战码明文结构

`buildCond()` 编出的条件串含：难度 + 9 项实验开关 + 车道数 + 模式 + 种子 + 分数。`DIFF_ORDER` / `EXP_ORDER` 定位顺序。`applyCond()` 导入时完整复现，仅本局、不写存档。

老码 `CZYFK-XX-种子-分数`（XX = PT/EX/CM/MX）走 legacy 分支，结算页标注「本码是老版挑战码，无法确定是否为真实的模式」。

### 3.3 装逼码

`buildBoastCode()` → `CZYBB-JX-…`，只用于极限局炫耀分数、验真伪，**不能开局**。`verifyBoast()` 校验。

## 4. 专属编码与验证码 🔴

- `makeCode(lv)`：`'CZYBD-' + codeSeal('BD.'+lv+'.'+随机数)`，每个级别通关发一个。
- `verifyCode(t)`：解出 `BD.lv.xxx`，查 `LEVELS` 返回 `{ok, lv, badge, need}`。
- 主菜单「验证码」页：`verifyGo` 先 `verifyCode`，再退化尝试 `parseLevelCode`（允许直接查等级码本身）；显示「✅ 真实 · 第 N 级 · 称号「X」· 目标 Y 分」或「❌ 编码无效或被改动过」。
- 专属编码在 **个人主页** 展示；主界面顶部展示**称号徽章**（`renderMenuBadge()`，取最后一个称号）。

> 用户要求的呈现：主界面展示称号、个人主页展示编码，且个人主页有一句话「别忘记把存档码发给开发者哦」——这是你收集玩家存档码的引导语。

## 5. 账户系统

- 数据存 `save.accounts`，键为账户名（`accKey()` = trim 后截 20 字符）。每个账户：
  ```js
  {pw:'…', coins:0, score:0, badges:{}, saveCode:''}
  ```
- 登录 / 注册是两套独立 UI（分段 tab）：
  - 注册 `accRegister`：填两次密码，一致才建号，注册后自动登录。
  - 登录 `accLogin`：只认已有账户，不自动注册。
  - 非强制：不登录也能玩全部游戏功能。
- `loggedIn`（模块级）为当前登录名；`save.profile` 持久化。
- `renderMenuBadge()`：主菜单徽章带登录名前缀；`renderProfile()`：个人主页显示金币 / 最高分 / 称号 / 编码。

> 玩家手册可以讲"账户怎么用"（这是玩家功能），但**不能**讲后台管理、密码、参数字段。

## 6. 后台管理（密码 + 命令 + 操作）🔴

### 6.1 两级密码

| 密码 | 权限 |
|------|------|
| `devczy` | **只读**：打开管理界面，看账户 / 金币 / 积分，操作列显示「（只读）」 |
| `cczzyyopen` | **全开**：一次获得修改权限，可新建 / 删除账户、增减金币积分、导入存档码 / 配置码 |

同时 `devczy` 也是开发者模式的总密码（`CONFIG.devPassword`，`type on devczy`）。

### 6.2 入口（隐藏命令，不进命令书 / 玩家手册）

在主菜单「高级」输入框里输入：

- `admin-view` → 等价 `openAdmin('devczy')`，只读打开。
- `admin-edit` → 等价 `openAdmin('cczzyyopen')`，全开。
- `admin-pw <密码>` → 用任意密码尝试打开（对了才进），便于临时输入上面两个密码。

`openAdmin(pw)`（约 2299 行）：`devczy` 置 `adminView=true`；`cczzyyopen` 置 `adminView=true; adminEdit=true`。

### 6.3 管理界面操作（`renderAdmin()`，约 2304 行）

表格四列：**账户 / 金币 / 积分 / 操作**；顶部「新建账户 / 删除账户」。

- 点账户名选中（`adminSel`）。
- 每行操作（仅 `adminEdit` 可见）：`导入存档码`、`+100币`、`-100币`、`+100分`、`-100分`。
- 新建账户：内联输入框（账户名 text + 密码 password 同款样式），初始金币 / 积分 0。
- 删除账户：先选中再删。
- 存档码保存：选中账户 → 粘贴对方存档码 → `decodeSave()` 校验 → 存进该账户的 `saveCode`。
- 返回：`adminBack` → `advLayer`（高级面板）。

### 6.4 远程增减的标准流程

1. 玩家把存档码发给你（个人主页有引导语）。
2. 你输 `admin-pw cczzyyopen` 进后台全开。
3. 点列表选中该账户 → 点「导入存档码」→ 粘贴 → 点下方「导入存档码」保存。
4. 用 `+100币/-100币`、`+100分/-100分` 增减，或导出 / 导入配置码批量改。
5. 改完让玩家重新导入你发回的配置码或存档码生效。

## 7. 存档敏感字段

`save` 里与机密相关的字段（新增字段要四处同步：`DEFAULT_SETTINGS` 覆盖、`save` 初始、两处硬编码重置）：

| 字段 | 用途 |
|------|------|
| `coins` | 金币总数 |
| `lane1Cleared` | 一车道通关奖励领取标记 |
| `seenTips` | 教程已读标记 |
| `shopBought` | 商店已购 |
| `accounts` | 账户字典（含密码、金币、积分、徽章、存档码） |
| `profile` | 当前登录名 |
| `officialDone` | 5 级奖励领取标记（去重） |
| `badges` | 已获称号字典 |
| `codes` | 各级别专属编码 |

> ⚠️ 两处硬编码 `save={...}` 重置（`gameOver` 极限分支、`setDelete`）必须包含全部新字段，并调 `resetSkinVisual(); stopBgm();`。

## 8. 配置码格式（远程增减）🔴

- 导出 `adminExport`：
  ```js
  var cfg={accounts, officialDone, badges, codes, coins};
  'FKCC-CFG:' + btoa(unescape(encodeURIComponent(JSON.stringify(cfg))))
  ```
- 导入 `adminImportCfg`：校验 `FKCC-CFG:` 前缀 → base64 解 → JSON.parse → 逐字段覆盖 → 写存档。
- 用途：你可以把改好的账户 / 金币 / 积分打包成一段码发回给玩家，玩家导入即生效；或反过来收玩家的配置码在本机改。

> 配置码是 base64 明文，**不等于加密**，别在里面放真正敏感的私密信息；它只是便捷传输格式。

## 9. 改动红线与发布清单

1. **等级码只认固定 5 段**：改 `LEVELS.need` → 必须重新导出 5 段码 → 更新本册 §2.2 表格 → 重新分发给需要的人。
2. **别动 `CODE_KEY`**：一改全部历史码失效。
3. **玩家手册零敏感**：改任何文档后跑测试断言（`cczzyyopen` / `admin-view` / `admin-edit` / `LEVEL_CODES` / 「官方」不得出现在玩家向 md/txt）。
4. **项目内零「官方」字眼**：html 里搜不到；等级相关统一用「等级码 / 专属编码」。
5. **命令别名全局查重**：加命令 / 别名前全局搜。
6. **发布清单**：改 `CONFIG.appVersion` → `LOG` 补日志 → `node --check` → DOM 引用检查 → 冒烟测试全过 → `workbuddy_sites_deploy`（链接不变）→ 线上核对页脚版本号。
